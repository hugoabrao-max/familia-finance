Depois: list-deployments do serviço web até SUCCESS, /health com a nova APP_VERSION e md5 da página servida igual ao do app rodando localmente com o mesmo commit (de dentro do sandbox, conferir via pg_net: net.http_get). Motivo da mudança (12/11/2026): Functions do Railway têm limite de 96 KB por arquivo (a v0.15.0 tinha 98.205 bytes; a v0.16.0, 107.943, era aceita e descartada sem aviso). O serviço app (Function, v0.15.0, sem domínio) foi removido em 13/11/2026 a pedido do Hugo; para voltar atrás, usar o rollback de deploy do web (canRollback) ou republicar um commit anterior.
Edge Functions: deploy_edge_function mantendo verify_jwt (pluggy-sync, backup-export: false com token próprio; member-invite: true). Código em supabase/functions/.
Banco: apply_migration; depois exportar a migração para supabase/schema/migrations/<version>_<name>.sql e o objeto alterado para supabase/schema/live/ (conferir md5 com scripts/verify-export.sql).
Sincronização: pg_cron pluggy-sync-diario (15 1,3,10,22 * * * UTC) chama pluggy-sync via pg_net com x-sync-token lido de app_settings; pos-sync (25 1,3,10,22 * * * UTC) roda post_sync(). O item MeuPluggy atualiza sozinho ~01:02 UTC; não forçar refresh.
Backup: serviço Railway 'backup' (cron diário 0 9 * * * UTC = 05:00 Cuiabá) → GET backup-export (token) → gzip → bucket 'backups' (iad) → relê/hash → POST /report. Registro em backup_runs. Exporta todas as tabelas de public.
Restauração: serviço Railway 'restore-check' (cron semanal 0 10 * * 0 UTC = domingo 06:00 Cuiabá, entre o backup das 09:00 e o sync das 10:15; também a cada deploy/redeploy) → último objeto do bucket → POST backup-export/restore → restore_backup_to_test() em esquema restore_test → compara o restaurado com o próprio backup (alarme se a produção tiver menos lançamentos que o backup) → backup_runs RESTORE_TEST_OK/DIVERGENT.
Recuperação total: projeto Supabase novo → migrações na ordem de version → reaplicar supabase/schema/live (views, funções, políticas, cron, trigger on_auth_user_created em auth.users) → secrets Pluggy → restaurar JSON do bucket com jsonb_populate_recordset nas tabelas públicas (mesma lógica de restore_backup_to_test, sem o prefixo restore_test) → recriar tokens em app_settings → ajustar SUPABASE_URL/publishable key no app.ts → pluggy-sync.
